# MSS Knowledge v0.1.0 verification record

This document records evidence for the first verifiable release. A pushed commit is not treated as a verified release until the corresponding checks have completed successfully.

## Target vertical slice

The v0.1.0 target is:

1. start PostgreSQL, Redis 8 Query Engine, Gateway, Worker, and an S3-compatible object store;
2. authenticate with a development bearer token;
3. expose authorization-filtered knowledge-base catalog data;
4. upload and asynchronously import at least one TXT or Markdown document;
5. search active, authorized chunk projections through REST;
6. fetch an active, authorized chunk through REST;
7. expose the same read-only `search`, `fetch`, and `list_knowledge_bases` operations through MCP Streamable HTTP;
8. verify tenant isolation, active-version filtering, citations, migration rollback, and Redis rebuild behavior.

## Verified read checkpoint

Commit `417e4dcd748a957ff59fd1bcf5389d6764e5e7e7` completed the available GitHub Actions gates for the authenticated read path.

The underlying read implementation was committed as `2810cf3cc332346c22a72cc3b5d1a27eea012359` and includes:

- static bearer authentication for development and test environments only;
- PostgreSQL authorization-filtered knowledge-base catalog access;
- Redis Query Engine chunk indexing, hybrid lexical/vector retrieval, exact fetch, and RRF fusion;
- deterministic local embeddings for repeatable verification, not production semantic quality;
- REST endpoints for catalog, search, and fetch;
- read-only MCP tools for catalog, search, and fetch;
- active-version and final ACL revalidation.

## Verified S3 checkpoint

Commit `daa804ff98cf3c51e9ad51574426e23c1136573f` added a version-aware S3-compatible object-store adapter with:

- explicit bucket and canonical object-key boundaries;
- bucket-versioning validation;
- immutable object-version references;
- SHA-256 streaming and write-after-read verification;
- explicit-version open, stat, and delete operations;
- bounded configuration for S3-compatible endpoints.

The adapter has passed a real S3-compatible MinIO integration workflow covering bucket versioning, put, head, get, immutable-write conflict handling, explicit version deletion, and cleanup.

## Current implementation boundary

The system now has both sides of the API boundary:

- durable authenticated document submission into S3 and PostgreSQL;
- authenticated REST and MCP knowledge retrieval from active Redis projections.

The asynchronous processing bridge between those boundaries is not yet wired. The Worker still runs in foundation mode and does not claim jobs. Therefore an uploaded document remains pending and cannot yet become searchable without manually created projections.

## Remaining release work

- wire the Worker job loop and lease/fencing lifecycle;
- execute S3 open, native parsing, structural chunking, deterministic embedding, Redis indexing, verification, and atomic document-version publication;
- persist normalized documents and chunk manifests to S3;
- add S3-compatible storage and bootstrap services to the Compose topology;
- add one automated upload-to-READY-to-search-to-fetch end-to-end test;
- exercise Redis deletion and full rebuild from PostgreSQL plus S3;
- verify the MCP read path against the running release-candidate deployment;
- update the release candidate documentation and remove temporary checkpoint workflows.

Production OIDC and public ChatGPT/Grok interoperability remain post-v0.1 validation items unless a reachable OAuth-capable deployment is available during release validation. The v0.1 release remains intentionally limited to TXT and Markdown plus deterministic local embeddings so the entire path can be reproduced without paid model APIs.
